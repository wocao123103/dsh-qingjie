# CCF-A 研究流程（蒸馏版 · v2）

> 来源：CCFA-Skills（MIT，© Chaoyue Li）。本文件是**压过的执行版**，不是原文复制；上游 18 个 SKILL.md、绘图库、配置台未包含。
> 工具配套：`qingjin_flow(action=route)` / `qingjin_humanize` / `qingjin_check` / `qingjin_lookup(scope=glossary)` / `qingjin_related` / `qingjin_pdf_read` / `qingjin_export`。

## 30 秒决策

```
用户要什么？
├─ 判断（值不值得做 / 能不能投 / 有没有硬伤）→ 评审批次，不动正文
├─ 生产（写 / 改 / 画 / 排版）            → 写作批次，先确认授权范围
├─ 证据（实验怎么做 / 结果怎么讲）          → 实验批次，先建 claim-evidence 矩阵
└─ 应答（rebuttal / 重投）                → 应答批次，先分 issue，再谈承诺
```
**先定性，再动手。** 一次只走一个批次；交接时复用已生效规则，只补变化的部分。

## 0. 两个前置（每次都要）

1. **表达前置**：直接说事实、证据与决定；不预设审稿人、不写空承诺、不写过程旁白。
2. **边界前置**：确认这次是「判断」还是「改写」。评审不代写正文，写作不改研究结论。

## 1. 路由表

| 用户的话 | 批次 | 产出 | 明确不负责 |
|---|---|---|---|
| 这方向值不值得做、创新够不够 | 选题判断 | 价值/创新/机制逻辑评审 | 不因缺实验扣分 |
| 只有一个模糊想法 | 选题发展 | 问题—洞察—方法—证据链 | 不追求排名 |
| 找相关工作、数据集、baseline | 文献 | 带链接的清单 | 不替结果下结论 |
| 怎么证明机制有效 | 实验设计 | claim-evidence 矩阵 + 消融 | 不虚构数字 |
| 要落代码/复现/训练报错 | 工程 | 可运行代码与诊断 | 不用简化模型冒充方法 |
| 数字改了，前后还对得上吗 | 核验 | 不一致清单 | 不改正文 |
| 帮我审这篇 / 能不能投 | 评审 | 结构化评审报告 | 不在评审中改写正文 |
| 写正文、润色、压缩 | 写作 | 稿件修改 | 不擅自改问题与方法 |
| 太像 AI 写的 | 表达 | 改写建议 + 保留清单 | 不删真实局限与负结果 |
| 回复审稿意见 / 重投 | 应答 | 逐条回复 + ledger | 不只写致谢与承诺 |
| 画架构图/数据图 | 绘图 | 图 + 可复用源文件 | 不挑数据集与指标 |
| 交稿前检查 | 投稿 | 模板/页数/匿名清单 | 不新增实验 |

需要机器路由：`qingjin_flow(action=route)(task="...")`。

## 2. 写作纪律

1. **先句间关系，后措辞**：下一句必须解释、支撑或推进上一句；加连接词不能替代缺失的理由。
2. **先科学点，后风格**：用领域最普通的词把机制说清，再谈好不好看。
3. **删掉想象出的审稿人**：`为了严谨起见`、`需要说明的是`、`我们相信这将…`、无数字的`显著优于`、`首先/其次/最后`三段式。
4. **保留**：真实批评与反例、标定不确定度、负结果、协议事实、引用、公式、数字、术语、必要披露、作者自己的句尾收束。
5. **内部旁白留在 rebuttal**：`本版本`、`按要求修改`、`上一版` 不属于正文。

跑：`qingjin_humanize(text)`。

## 3. 实验设计（claim-evidence 矩阵）

**核心规则**：实验必须能区分「核心假设」与「合理替代解释」；便宜的代理实验不能悄悄替代原问题。

先建矩阵，再排跑：

| 主张 | 需要什么证据 | 数据集/负载 | 对照 | 指标 | 区分什么 |
|---|---|---|---|---|---|
| C1 机制有效 | 主实验 | | 基线 + 同预算 | | 有效 vs 无效 |
| C2 是 X 而非 Y 在起作用 | 消融 | | 去 X / 去 Y | | X 的独立贡献 |
| C3 在边界条件下仍成立 | 鲁棒性 | | 扰动/跨域 | | 失效边界 |

**四种模式**：`design`（设计）· `result-template`（空表骨架）· `result-presentation`（真实结果转表/图规格）· `research-iteration`（能区分解释的下一轮实验）。

**纪律**：
- 空值一律用 `—`（Markdown）或 `\emptycell`（LaTeX），**绝不填估算数字**；
- 报告的方法版本必须确认过完整配置，不能拿简化版当目标方法；
- 冒烟测试只覆盖改动过的关键路径，不做重复防御性实验；
- **区分「命令失败」与「科学上的负结果」**：前者修实现，后者是结论；
- 一个指标变好不等于科学成功，更不等于可以投稿。

## 4. 评审纪律（最关键）

**四模式**：`scientific` · `writing` · `full` · `version-comparison`。
**七维度**：新颖性 · 正确性 · 证据 · 意义 · 清晰度 · 可复核性 · 伦理与局限。
**报告规模**：scientific/full 14 节；writing 9 节；用户明确要简版才用 5 块。

**发现四分类**（不许混）：
- `confirmed-flaw`：能在稿子里指到位置的硬伤
- `unsupported-claim`：主张超出证据，但未必错
- `clarification`：需要澄清，不是错误
- `missing-input`：缺材料，无法判断

**反证纪律**：每条 major/critical 意见，先在被引位置或附录里找**最强反证**；被反驳就撤回或缩小。少于一步反证，等于没有。

**禁止**：虚构引用、虚构缺失相关工作、无参照集的百分位排名、凭感觉给录用概率、边审边改正文。
**分开报**：质量分 / 置信度 / 覆盖范围，三者不合并成一个数。
**复审两问**：① 现在够不够投？② 这次修订是否真的进步？

## 5. Rebuttal 与 Revision Ledger

**四模式**：`rebuttal`（限时/限字应答）· `revision-ledger`（逐条台账）· `response-letter`（修改说明）· `resubmission`（改投）。

**第一步是分 issue，不是写稿**。按审稿人 → 关切成因 → 严重度 → 现有证据分组；重复意见合并但保留归属。

**先答四类高影响问题**：soundness · novelty · 缺证据 · 错误假设。

**承诺纪律**：
- 只承诺**可行且已授权**的修改；
- 严格区分「已完成的改动（附位置）」「计划中的实验」「口头承诺」；
- 声称改过某处前，先确认位置真的改了；
- 简洁的事实澄清不是科学让步；不写多余道歉与防御性重复。

**台账列**：`审稿意见 → 动作 → 稿件位置 → 负责人 → 状态`。全程维护**一份**，不要每轮新建。

```text
模式：
venue 与限制（字数/截止/分数）：
issue 表：
逐条应答草稿：
承诺的稿件改动：
ledger：
需要规避的说法：
```

## 6. 投稿检查

- 模板与年份：用**当年** CFP，别用旧指南。
- 页数：正文与附录分开算，参考文献是否计入。
- 匿名：作者、致谢、仓库链接、图片元数据。
- 必需声明：LLM 使用声明（CVPR 2027 据说不例外）、可复现性、伦理、局限。
- PDF：字体嵌入、位图 ≥300 dpi、线条图矢量、书签与元数据。
- 补充材料：编号与正文一致。
- 数值与图：所有报告数字来自真实运行；图与表口径一致。

## 7. 产物

`ccfa-workfiles/<任务用途>/<具体产物>/`，例：`figures/method-overview/`、`reviews/paper-short-title/`、`literature/retrieval-memory/`。
同一产物共用目录；迭代更新原文件；不用 `temp`/`misc`/`final-final`；失败生成不覆盖可用结果。

## 8. 反模式（看到就停）

- 为了显得专业而加一段不改变判断的话；
- 用一个更好的指标代替对原问题的回答；
- 评审意见没复现就写进报告；
- rebuttal 里承诺没做过的实验，或把计划写成已完成；
- 把「缺材料」当成「结论错误」；
- 把「命令失败」当成「方法不行」。

## 10. 交付前自检

- [ ] 回答的是用户真正问的那个问题吗？
- [ ] 判断/改写/实验/应答的批次有没有混淆？
- [ ] 每条主张都能指到位置或证据吗？
- [ ] 有没有删掉真实局限、负结果或披露？
- [ ] 分数、置信度、覆盖范围分开写了吗？
- [ ] 承诺的改动是「已完成」还是「计划中」，标清楚了吗？
